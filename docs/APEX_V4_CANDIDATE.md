# Apex 4.0.0 independent strategy candidate
Status: **demo source / research only**. No release manifest change, compiled EX5, live deployment, or existing EA replacement. This is not a validated profitable strategy.
 
## Intended design
- Separate EA, no reference-trader entry authority, no OpenAI calls or external-model research. Existing Apex dashboard, vault and chat are unchanged. New EA never uses the legacy AI bridge. Existing installed EAs still use their configured strategy until explicitly replaced.
- Direct XauCloud POST /api/cloud/apex/outlook-v4 (companion XauAI-Sniper branch dev/apex4-direct-outlook-candidate); the license/account is validated, cloud armed state checked, fresh globally published STRONG grade and source verified. No notification wait or model tool calls. One small response per poll, locally paced entries.
- All basket positions have common broker-side SL and TP2. No profit requirement for an additional entry. Explicit demo-only margin stress mode; bounded layers, quote geometry, spread, equity cushion and no ambiguous order retries. Default is risk-bounded demo mode, stress mode is opt-in. Not a promise of fill rate or margin availability.
- User tiers: USD equity at basket start $20–49.99=.01, $50–99.99=.02, $100–199.99=.05, $200–499.99=.10. Proposed extra tiers $500–999.99=.20 and $1000+=.50. Broker volume step/min/max enforced. Under $20 no entry. Max demo layers default 40, hard cap 200. 250ms local pacing default, synchronous broker fill acknowledgement may take longer. Entry window default 25 seconds; no chasing TP1 or entry deviation; authorization expires after 8 seconds if not refreshed.
- Countertrend pullback prototype uses closed M1/M5, impulse/ATR, exhaustion proxy, break of microstructure, invalidation and retracement target. No assertion that it is learned/calibrated from XauCloud history yet. Pullback evaluation is independent of Outlook but requires recent cloud armed response. Reserve first two minutes of the hour for Outlook. Do not silently use another account's positions; distinct magic and USD demo hedging only. No live orders.
- Source candidate includes broker stop/target, restart no new entries with existing exposure, persistent terminal-local signal IDs and terminal-local lock. A cross-terminal durable claim, complete order/deal audit and Command Center telemetry remain release blockers. After restart existing orders retain broker-side SL/TP, not reconstructed local basket management.
 
## Validation
Run node --test tests/apex-v4.test.mjs; separately compile EA with MetaEditor and test real ticks and isolated demo, including restart, price gaps, rejection, partial fill, disarm, TP2, SL, and source loss. Companion endpoint must be deployed to a staging/test environment before integration. Test auth, rate, backend load, and latency. Verify exact broker contract, margin and spread (unlimited leverage does not eliminate trading losses).
 
Export chronological historical Outlook rows including publication-time grade, realized R, TP1/TP2 first touch and latency. Run hourStudy on disjoint out-of-sample period, verify sample size, net costs, win rate, drawdown and actual fast-target distribution. 08:00, 09:00, 10:00 WAT are requested candidate hours, not proven best hours. STRONG is required in all hours until a time-based policy is independently validated. Use actual XauCloud price archive and trading cases to calibrate the pullback detector before promotion; compare with existing native Apex and measure false positives, stop-outs and ruin. Do not optimize on evaluation data. A research simulation is not a broker backtest.
 
No production merge or release until compiled and independently verified. Real-money automation, including full-margin accumulation, is deliberately not enabled by this candidate. Use only explicitly authorized risk-bounded execution after validation.
